# CLAUDE.md — driver-mobile

Guidance for working in this app (`apps/driver-mobile`). This file is scoped to the driver mobile app only.

## What this is

The **driver-facing mobile app** for the dispatch engine. Drivers log in, view their assigned jobs, and receive push notifications for new assignments. Built with **Expo (SDK 55) + React Native 0.83**, TypeScript, and NativeWind (Tailwind) for styling.

## Tech stack

- **Expo SDK 55** (managed workflow — `android/` and `ios/` are generated by prebuild, not hand-edited by default)
- **React Native 0.83.6**, React 19.2
- **expo-router** for routing, **expo-secure-store** for token storage
- **NativeWind 4** (`className` on RN components) — config in `tailwind.config.js` / `global.css`
- **@react-native-firebase/app + /messaging** for push notifications (FCM)
- **Jest + jest-expo** for tests
- Shared code comes from the monorepo `libs/shared/*` via `@dispatch/shared/*` path aliases (see `tsconfig.json`)

## Layout

Layer-based structure — group by technical role. Each `src/` folder has a matching path alias (see below).

Routing is **Expo Router** (file-based) under `app/`; presentational screens/components live in
`src/` (layer-based, each folder has a matching path alias). Route files stay thin — they wire
router/auth handlers into `src/screens/*` components.

```
app/                          # Expo Router routes (see "Navigation")
  _layout.tsx                 # Providers + themed StatusBar + root Stack
  login.tsx                   # Public auth screen
  settings.tsx                # Modal route
  (app)/                      # Authenticated area (auth guard)
    _layout.tsx               #   redirect to /login when signed out
    (tabs)/                   #   bottom-tab group (BottomNav custom tabBar)
      _layout.tsx, index.tsx, route.tsx, pay.tsx, activity.tsx, profile.tsx
    job/[id].tsx              #   job detail, pushed over the tabs
src/
  components/ui/              # Reusable presentational components (primitives)
  screens/
    LoginScreen.tsx           # Email/password login; registers push token on success
    JobsScreen.tsx            # Authenticated job list; subscribes to foreground push
  services/
    api/          client.ts   # Wraps @dispatch/shared DispatchApiClient (+ index barrel)
    storage/      *.ts         # SecureStore-backed token storage (+ index barrel)
    notifications/fcm.ts       # Firebase Cloud Messaging integration (+ index barrel)
  hooks/                       # Custom React hooks
  contexts/                    # React contexts (e.g. AuthContext)
  navigation/                  # Navigation config
  constants/                   # App-wide constants
  types/                       # Shared TypeScript types
  utils/                       # Helpers
```

Each `services/*` subfolder has an `index.ts` barrel, so import from the folder (`@services/api`) rather than the file (`@services/api/client`).

Auth is token-based: access/refresh tokens live in `expo-secure-store` under `dispatch.access_token` / `dispatch.refresh_token`. `AuthProvider` (`@contexts`) exposes `{ session, isLoading, signIn, signOut }`; the `app/(app)/_layout.tsx` guard redirects to `/login` when there's no session.

## Navigation

**The app uses Expo Router (file-based routing). Do NOT hand-roll navigation** with `useState` +
conditional rendering, or present screens as manual boolean overlays. (That was the original
mistake — tabs unmounted on switch, Android back was broken, no deep linking, settings was a fake
overlay. This is exactly what the Expo Router migration fixed; don't reintroduce it.)

Conventions:
- **Entry** is `expo-router/entry` (`package.json` `main`). There is no `App.tsx`; app-wide
  providers live in `app/_layout.tsx`.
- **Routes** live in `app/`. `(app)` is the authenticated group (one auth guard covers all
  children); `(tabs)` is the bottom-tab group; **detail screens are pushed routes** (e.g.
  `app/(app)/job/[id].tsx`) so they cover the tab bar; **Settings is a modal route** (`app/settings.tsx`).
- **Tabs** use our `BottomNav` design via the custom `tabBar` adapter `@navigation/AppTabBar` —
  do not replace it with the default tab bar. Tab icon/label config lives in `AppTabBar`'s `TAB_META`.
- **Screens stay presentational** (`src/screens/*`): they take callback props; the thin route files
  inject `router.push(...)` / `useAuth()` handlers. Navigate with typed hrefs
  (`router.push({ pathname: '/job/[id]', params: { id } })`); typed routes are enabled
  (`app.json` → `experiments.typedRoutes`).
- **Deep links**: scheme is `driver-mobile://` (`app.json`); FCM taps route via
  `setupNotificationRouting()` (wired in `app/_layout.tsx`). Cold-start deep links need the native
  manifest's scheme intent-filter — regenerate with `expo prebuild` if it's missing.

## Path aliases

Import via per-folder aliases, not relative paths. Defined in **both** `babel.config.js` (runtime, via `babel-plugin-module-resolver`) and `tsconfig.json` (types) — keep the two in sync when adding an alias.

| Alias | Path | | Alias | Path |
|---|---|---|---|---|
| `@components` | `src/components` | | `@navigation` | `src/navigation` |
| `@screens` | `src/screens` | | `@constants` | `src/constants` |
| `@services` | `src/services` | | `@types` | `src/types` |
| `@hooks` | `src/hooks` | | `@utils` | `src/utils` |
| `@contexts` | `src/contexts` | | `@theme` | `src/theme` |
| `@dispatch/shared/*` | monorepo `libs/shared/*` | | | |

Example: `import { login } from '@services/api';`

> Note: `@types` aliases the local `src/types` folder. This only affects module specifiers you `import` explicitly; ambient DefinitelyTyped packages (`@types/react`, etc.) load via `typeRoots`, so they're unaffected. Don't `import` from a `@types/*` npm package by specifier in app code.

## Important gotchas

- **Not Expo Go compatible.** Because of the `@react-native-firebase` native modules, this app must run via a **development build** (`expo run:android`), not the Expo Go client.
- **`npm start` is bash-only.** The `start` script prefixes `NODE_OPTIONS=...` inline, which fails in PowerShell/cmd. On Windows, run `npx expo start --dev-client` (optionally `$env:NODE_OPTIONS="--dns-result-order=ipv4first"` first).
- **Firebase requires `google-services.json`.** Prebuild fails without `expo.android.googleServicesFile` set in `app.json`. A **placeholder** `google-services.json` is committed so the app builds and runs; **replace it with the real file from your Firebase project** (package `com.dispatch.drivermobile`) for push to actually work. FCM code in `fcm.ts` no-ops gracefully when messaging is unavailable.
- **Assets are placeholders.** `assets/*.png` (icon/splash/adaptive-icon/favicon) are solid-color placeholders. Replace with real artwork before shipping.
- **`android/` and `ios/` are gitignored (managed workflow).** They're generated by `expo prebuild`, not committed. Do all native config via `app.json` + config plugins so it survives regeneration — never hand-edit `android/`/`ios/` as the source of truth (a `prebuild --clean` wipes it).
- **API base URL** comes from `EXPO_PUBLIC_API_BASE_URL` (see `.env.example`, defaults to `http://localhost:8000`). Copy `.env.example` to `.env` and set it.

## Theming (light/dark × 8 accent themes)

Colors are **semantic tokens**, never hardcoded hues. Use token classes
(`bg-background`, `text-foreground`, `bg-primary`, `text-primary-foreground`,
`bg-primary-muted`, `border-border`, `bg-card`, `bg-surface`, `bg-input`,
`text-muted`) so everything re-themes automatically. Do **not** use raw palette
classes like `bg-blue-600` or `text-gray-900` in app UI.

How it works:
- `src/theme/themes.ts` — token values as `"R G B"` channels: shared light/dark
  neutrals + 8 accent themes (`blue`, `violet`, `emerald`, `rose`, `amber`,
  `teal`, `indigo`, `slate`). Each theme defines only its primary ramp.
- `tailwind.config.js` maps each token to `rgb(var(--color-<token>) / <alpha-value>)`.
- `global.css` `:root` holds default (blue/light) values as a fallback.
- `ThemeProvider` (`src/theme/ThemeProvider.tsx`) applies the selected
  theme+mode as inline CSS variables via NativeWind's `vars()` on a root View;
  descendants inherit them, so a change updates the whole tree instantly.
  Preferences (`mode`, `themeName`) persist in AsyncStorage.
- `useTheme()` gives `{ mode, themeName, scheme, palette, setMode, setThemeName }`.
  Use `palette.<token>` (an `rgb()` string) for **imperative** color props that
  can't take a className — `ActivityIndicator` color, `RefreshControl`
  tint/colors, `TextInput` `placeholderTextColor`, `StatusBar` style.
- `SettingsScreen` (`@screens/SettingsScreen`) is the Appearance UI: Light/Dark/
  System selector + 8 swatches + live preview. Reachable from Login and Jobs.

Adding a token: add it to `TOKEN_NAMES` + neutrals/accents in `themes.ts`, the
`colors` map in `tailwind.config.js`, and the `:root` block in `global.css`
(three places, keep in sync). Adding a theme: add an entry to `THEMES`.

## NativeWind (Tailwind) — required wiring

NativeWind v4 only applies `className` styles if **all** of these are in place. If the UI renders unstyled (plain black text, no layout), one of these is missing:

- **`metro.config.js` must wrap the config**: `module.exports = withNativeWind(config, { input: './global.css' })`. Without this the CSS pipeline never runs and every `className` is silently ignored — this is the #1 cause of "Tailwind isn't working".
- **`babel.config.js`**: `nativewind/babel` goes in **`presets`**, not `plugins` (v4 change), and `babel-preset-expo` needs `{ jsxImportSource: 'nativewind' }`.
- `global.css` (the `@tailwind` directives) must be imported once at the app root (`App.tsx`) and referenced as the `input` above.
- `tailwind.config.js` `content` globs must cover `App.tsx` + `src/**`.

## First-run / troubleshooting notes

This app was scaffolded but not fully wired at first, and hit a series of first-boot issues. If you're setting it up fresh or see similar errors:

- **`metro.config.js` resolver**: keep `disableHierarchicalLookup = false`. Setting it `true` stops Metro from seeing packages npm nests under a dependency's own `node_modules` (e.g. `expo-modules-core` under `node_modules/expo`), causing false "Unable to resolve" errors for packages that are actually installed.
- **`react-native-css-interop`** (NativeWind's runtime) is nested under `nativewind/node_modules` due to a peer conflict, so it's aliased in `metro.config.js` `extraNodeModules` — don't remove that alias.
- **SecureStore keys must match `[A-Za-z0-9._-]`.** Colons throw `Invalid key` at runtime (why `secureTokenStorage.ts` uses `dispatch.access_token`, not `dispatch:...`).
- **Native build quirks** (regenerate from `app.json`, but if a fresh prebuild misses them): adaptive icon references `@color/iconBackground` — if absent from `res/values/colors.xml`, add `<color name="iconBackground">#1d4ed8</color>`; ensure `android/app/build.gradle` `namespace`/`applicationId` are `com.dispatch.drivermobile` (from `app.json` `android.package`).
- **Don't run `expo install <pkg> -- --save-dev`** — the `--` gets mis-parsed and npm prunes unrelated packages. Use `npx expo install <pkg>` (add `--dev` via the Expo flag if needed).

## Dependency management

This is an Expo project — align dependency versions with the SDK using Expo's tooling, not manual bumps:

```bash
npx expo install --check    # report mismatches
npx expo install --fix      # update to SDK-compatible stable versions
```

If Metro reports a core package (e.g. `expo-modules-core`, `@expo/config-plugins`) as unresolvable, it's usually a **nesting/hoisting** issue, not a truly missing package — check with `npm ls <pkg>` before installing. A plain `npm install` (no delete) reconciles the tree fast; only delete `node_modules` as a last resort.
